# Cards

The cards of one area, in their order.

## GET /api/data/cards

### Parameters

| Name | Type | Required | Description |
|------|------|----------|-------------|
| `areaId` | integer | yes | The area whose cards you want. |
| `done` | boolean | no | `true` for only the cards that are done, `false` for only the open ones. |
| `assignee` | string | no | Only the cards this user id is on, alone or with others. |
| `unassigned` | boolean | no | `true` for only the cards nobody is on. |
| `dueBefore` | string | no | Only the cards due before this moment, as ISO 8601. A card with no due date is left out. |

The filters narrow one another: `?areaId=10&done=false&unassigned=true` is the
open work in that area nobody has taken on yet. A `dueBefore` that is not a date
filters nothing. Archived cards are never in the list, and neither are the cards
of an archived area.

::code-example
#curl
```bash
curl -X GET "https://boards.example.com/api/data/cards?areaId=10" \
  -H "X-API-Key: $LOKALBOARDS_KEY"
```

#js
```js
const response = await fetch("https://boards.example.com/api/data/cards?areaId=10", {
  headers: {
    "X-API-Key": apiKey,
  },
});

if (!response.ok) throw new Error(await response.text());

const data = await response.json();
```

#react
```jsx
import { useEffect, useState } from "react";

export function Example({ apiKey }) {
  const [data, setData] = useState(null);

  useEffect(() => {
    const controller = new AbortController();

    fetch("https://boards.example.com/api/data/cards?areaId=10", {
      headers: { "X-API-Key": apiKey },
      signal: controller.signal,
    })
      .then((response) => response.json())
      .then(setData)
      .catch((error) => {
        if (error.name !== "AbortError") console.error(error);
      });

    return () => controller.abort();
  }, [apiKey]);

  return <pre>{JSON.stringify(data, null, 2)}</pre>;
}
```

`assignees` is everyone on the card, in the order they were put on it — a card
can be on several people. `assignee`, `assigneeName`, `assigneeImage` and
`assigneeType` describe the first of them, as they did before, so an
integration that only knows one person per card keeps reading a sensible
answer. `?assignee=<id>` finds a card by any one of its people.

Each card comes with what opening it shows: its `comments`, newest first, its
`labels`, its `reminders` in minutes before the due date, and its
`attachments` — their name, type and size; where the file itself is comes with
the card from [`GET /api/data/card`](/api/card).

`status` is `false` for open and `true` for done. `content` is Markdown — a
`- [ ]` line in it is a checklist item, and the counts on the card's tile come
from those. See [Cards](/docs/cards).
