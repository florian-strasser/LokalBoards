# Security

LokalBoards holds a team's plans, so an instance reachable from the internet
deserves a few minutes of setup beyond getting it to start. Most of what follows
is already the default; this page says where it is not, and what each setting
leaves open.

## Who can get in

**Turn sign-up off on an instance others can reach.** With
`NUXT_PUBLIC_SIGNUP=true`, the default, anybody who finds the address can make
an account — and every signed-in account can read every board set to
**public**. With it off, accounts come from three places only: the first
administrator, created at start from `NUXT_ADMIN_EMAIL` and
`NUXT_ADMIN_PASSWORD` when the instance has none; an administrator under
**Users**; and an invitation to a board, whose link lets the invited address
register even with sign-up off.

```dotenv
NUXT_PUBLIC_SIGNUP=false
NUXT_ADMIN_EMAIL=you@example.com
NUXT_ADMIN_PASSWORD=a-long-password
```

Single sign-on can take the place of passwords entirely — see
[Single Sign-On](/docs/single-sign-on), including how to limit it to your own
e-mail domain.

A sign-in lasts a day unless `NUXT_SESSION_MAX_AGE_DAYS` says otherwise.
Resetting a password through a link ends every session of that account, and
changing it ends all but the one it was changed in, unless asked to keep them.

## HTTPS in front

Run LokalBoards behind a reverse proxy that terminates TLS, and set
`NUXT_BOARDS_URL` to the `https://` address people use. That address is what
links in e-mails and single sign-on are built from, and it is how the instance
knows to mark its session cookie `Secure`. A proxy that sends
`X-Forwarded-Proto: https` does the same.

The published port listens on every interface of the host. With the proxy on
the same machine, publish it to the loopback interface only, so the plain-HTTP
port is not reachable from outside:

```bash
docker run -d -p 127.0.0.1:3000:3000 … florianstrasser/lokalboards:latest
```

## Limits on guessing

Each client address gets, in a quarter of an hour, ten failed sign-ins, five
requests for a password link and ten uses of one, and thirty API keys or OAuth
tokens that turn out wrong. Past that, the address is turned away until the
quarter is up. Behind a proxy, the address is read from what the proxy adds to
`X-Forwarded-For` — set `NUXT_TRUST_PROXY` as
[described for reverse proxies](/docs#behind-a-reverse-proxy) when more than
one proxy stands in front, or none.

The counts are kept in the memory of the process. Several copies of LokalBoards
behind a load balancer each count on their own.

## Files

A file attached to a card, a picture in a description, an avatar and a board's
cover are served from `/api/uploads/` under a long random name. Anybody with
that address can fetch the file without signing in — the name is the
permission, as with a shared link — so an address passed outside the team
passes the file with it. The browser keeps a file it has fetched for up to a
year; a CDN or proxy in front is told not to keep it at all.

An attached file is deleted from the disk with the last attachment pointing to
it. A card in the archive keeps its files until the archive is emptied, after
`NUXT_ARCHIVE_RETENTION_DAYS` days — thirty unless set.

Only pictures and PDFs open in the browser. Every other file, whatever it says
it is, is sent to be saved, so a file somebody attached can never run as a page
of the instance.

## What leaves the instance

- **Webhooks** are delivered to public addresses only. The address is checked
  again at every delivery, against the address actually connected to, and a
  redirect is not followed — so a webhook cannot be pointed at the instance's
  own network. Give one a secret, and each delivery carries an
  `x-lokalboards-signature` header (`sha256=` and an HMAC of the body) for the
  receiver to check.
- **E-mail** goes only to the server in `NUXT_EMAIL_HOST`. Without one, no mail
  is sent at all — invitations still work through their links, but nobody can
  have a password link sent.
- Fonts, icons and scripts are all served by the instance itself. A browser
  opening LokalBoards asks no other server for anything, unless a picture in a
  card, an avatar or a board's cover is hosted elsewhere.

## Headers

Every response tells the browser not to guess a file's type, keeps the address
of the page somebody came from to the instance itself, and allows the instance
to be shown in a frame only by itself. A dashboard that embeds LokalBoards from
another address therefore shows an empty frame.

## Agents and API keys

An agent should have an account of its own, and a read-only key unless it has
to change things — see [MCP Server](/docs/mcp-server). Keys and the apps
connected over OAuth are listed, and revoked, in each person's settings.

## Reporting a problem

Please report a vulnerability privately, as
[SECURITY.md](https://github.com/florian-strasser/LokalBoards/blob/master/SECURITY.md)
describes, rather than in a public issue.
